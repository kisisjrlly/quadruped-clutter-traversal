# 系统设计草案

状态：架构候选，未实现。优先建立可解释、可调试闭环，避免同时训练整个系统。

## 数据流

机载传感器与关节/IMU → 时间同步与状态估计 → 带 unknown/置信度的局部三维地图 → 机身/落点/摆腿候选生成 → 全身碰撞及支撑可行性检查 → 短时控制执行 → 新观测重规划。

独立旁路：安全状态机监视延迟、状态有效性、姿态/力矩限制和环境接触。评测日志器读取执行真值/外部记录做审计，但不能反向给部署策略提供真值。

## 模块接口（待实现）

| 模块 | 输入 | 输出 | 关键约束 |
|---|---|---|---|
| 状态估计 | 带时间戳的 IMU、关节、里程计 | base pose/twist、关节状态、协方差 | 写明 frame、单位、时间戳来源 |
| 感知与记忆 | 深度/点云/RGB（按平台定）、状态 | 三维占据/未知空间、置信度、更新时间 | 不把未观察空间清空；保留后腿相关信息 |
| 动作候选 | 地图、状态、目标 | 短时身体姿态、四足落点、摆腿路径、接触时序 | 不能仅发 vx/vy/yaw 就声称控制所有落脚 |
| 全身检查 | URDF/碰撞几何、候选、地图 | 可行标志、净空、风险与拒绝原因 | 覆盖所有连杆与附件，不只足端 |
| 底层控制 | 可行参考、当前状态 | 关节命令/驱动力 | 受 SDK、关节、力矩、摩擦、稳定性限制 |
| 安全监督 | 当前状态、最近安全轨迹、健康状态 | 继续/减速/安全落足/保持/停止 | 失效时不可简单全电机断电导致跌倒 |
| 评测与回放 | 原始传感器、轨迹、物体位姿、事件 | 终止前记录与指标 | 与 actor 隔离、禁止 reset 后覆盖 |

## 最小算法路径

1. 使用明确的机体与四足碰撞几何，离线生成少量慢速参考动作，证明单步全身可行。
2. 采用足够表达落点和摆腿的控制接口；若设备仅开放速度命令，先判明是否满足研究目标，不直接接复杂导航器。
3. 以真实地图为输入做闭环基线，再接渲染/真实感知。训练不是几何问题的默认修补器。
4. 基线存在清晰性能瓶颈后，才选择学习局部动作候选、记忆表示或残差。蒸馏属于可选部署方案，不是既定多阶段训练承诺。

## 全身运动检查

设 q(t) 为机器人完整构型，B_l(q(t)) 为连杆 l 的占据体，O_j 为障碍。目标是对整个动作区间检查所有 B_l 与 O_j，不只是起点终点或几个机身检查点。落点安全不意味着摆腿安全，前脚安全不意味着后脚安全。

优先使用连续碰撞检测或经保守误差界验证的自适应细分。若仅离散采样，必须针对最细杆径、最大相对速度和旋转位移设计穿透漏检回归；不能任意指定 10 ms 便声称无漏检。支撑足、支撑多边形/动力学、摩擦、逆运动学和自碰撞也必须检查。

不确定性安全余量只能降低模型下的风险，不能在传感器漏检时保证真实世界零碰撞。

## 可观测性先验检查

对最细目标，在不同距离、角度、材料、光照和遮挡下实测检出率、点云连续性与定位误差。若杆在真实传感器里不可观测，须改布局尺度/传感器，或者降低相应能力主张；不能用无噪声射线代替真实能力。

## 运行预算

感知频率、地图更新时间、规划 p50/p95/p99 时延、控制周期、内存、显存均以实测为准。初稿不承诺固定频率、不借用无人机项目机器配置。过期地图与过期轨迹有独立 timeout 和安全处理。
