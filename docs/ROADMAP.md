# 开发与研究路线图

按验收门槛推进，不预设“几周训练必成”。每阶段先做最小闭环，再扩展场景。

| 阶段 | 交付 | 必须通过的验收 | 不通过时 |
|---|---|---|---|
| M0 立项与协议 | 本启动包、论文对照表、可运行评测逻辑 | 单测与文档一致；硬件/创新点标为待确认 | 修正定义，不开大训练 |
| M1 几何与接触闭环 | 机器人资产清单、全连杆模型、单障碍场景、接触/扰动记录 | 可回放安全一步；能检测足/小腿/机身故意轻碰；reset 不吞日志 | 查碰撞几何、控制接口、采样/标定 |
| M2 oracle 强基线 | 可行性见证、程序化场景、B0–B3、统一评测 | 未见可行场景能完成；各类失败可定位；完整预算/版本 | 收窄几何范围或改控制，不先训练视觉 |
| M3 onboard 感知闭环 | 带噪传感器模型、局部地图/记忆、同场景诊断 | actor 不读真值；细杆/后腿遮挡测试；报告 oracle 差距 | 先解决观测与同步 |
| M4 单一机制研究 | 选定 H1/H2/H3 中有证据的一项，完成强对照 | 同观测/同预算/同初态，消融与留出检验支持机制 | 加强基线或修改假设 |
| M5 真机分级验证 | 单障碍→稀疏→密集，独立审计视频与日志 | 无干预重复试验；接触与扰动可观测；完整失败记录 | 降低风险、回到对应模块 |
| M6 论文与复现 | 统计结果、方法、局限、资产/许可证、复现脚本 | 主张有证据、可一键重算、作者确认公开范围 | 不把演示视频当充分证据 |

## M1 的最小工作清单

先完成平台调查和控制权限表；选择一个引擎/机器人资产；构建平地+一杆+一瓶；接入按连杆区分的碰撞日志与物体全程位姿；演示一条无接触参考动作和三条故意接触的失败动作；输出保存回合文件与清晰回放。不做随机密集训练、域随机化大扫参或多个引擎同时适配。

## M2 基线定义

B0：既有稳定行走控制器+简单导航。只是工程下限，不能单独支撑新方法优势。

B1：机身三维避障+同一低层控制器。检查身体路径与真实腿部碰撞差距。

B2：B1+可行落脚点选择，但摆腿采用固定模板。检验落点/摆腿差异。

B3：全身几何约束+摆腿规划/优化+支撑可行性；优先作为强方法基线。

B4：部署观测受限的学习方法或已有强系统；根据资产/许可/实际复现成本选择，不能只选不匹配的弱算法。

oracle 与 onboard 分开，所有方法使用同一任务判据。B0–B3 是功能对照，不意味着必须把每篇相关论文完整重写。

## 不做的事情

初期不买新硬件、不宣称一个 GPU 足够、不设置固定发表期限、不为论文效果任意摆一个仅目标方法能过的场景。不启动无人看管的真机运动。
